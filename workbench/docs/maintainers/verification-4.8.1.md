# Version 4.8.1 verification

Audit repairs against 4.8.0 (`e3c9c8f`), requested by the owner on 14 October 2026.
The seven reproduced defects and three smaller implementation issues are repaired
in the distribution and the reference runtime regenerated by the installer.
The manuscript, bibliography, generated Makefile/editor fixtures, permission
rules and schema versions are unchanged.

Tested on Linux x86_64, Python 3.12.14, GNU Make 4.3, Git 2.51.1,
latexmk 4.83, ChkTeX 1.7.8 and pdfTeX from TeX Live 2023/Debian.

## Regression evidence

`tests/test_scope_4_8_1.py` contains 25 tests. Against the frozen 4.8.0 source,
22 fail (50 assertion failures across subcases); the three controls for actual
generated auxiliaries, mere filename mentions and output command arguments pass.
All 25 pass after the repairs. Each new test also catches one deliberate
production mutation in a disposable copy; 25 mutations, none surviving.

| Finding | Behaviour now verified |
|---|---|
| F1, auxiliary output containment | Conventional lists, indexes, glossaries and slide auxiliaries cannot follow an outside symlink. A real listings build with a `.lol` symlink fails before compilation and preserves sentinel bytes. |
| F2, source/output aliases | Outputs cannot alias their own or another document's root, in either default order, through hard links or symlinks. Known nonroot sources, authored `.idx` files, sources literally read at an output path, executable/interpreter scripts and explicit Makefiles are protected before the command runs. All six separated/attached Makefile option forms are covered. |
| F2 controls | Recorder-only `train.log` remains fingerprinted and becomes stale after editing. Actual generated `.aux` input is excluded. Merely mentioning an output filename or passing an output argument does not turn it into source. Repeated custom and Make builds still work. |
| F3, graphics freshness | Literal graphics search paths in included fragments are followed, including starred and explicit-extension commands. A real build consumes PNG, notices a newly added preferred PDF, becomes stale, then recompiles with the PDF and a current receipt. |
| F4, project checks | Literal and computed `.RECIPEPREFIX` cause conservative routing to the project's own `make check`; its custom recipe actually runs. |
| F5, manuscript integrity | Full and document checks reject conflict markers that a successful compiler command leaves undetected, including recorder-only text. Displayed files receive text integrity checks without unrelated format parsing. |
| F6, TeX comments | Zero through five preceding backslashes distinguish comments from escaped percent signs; a bibliography command after a line-break comment is ignored during installation. |
| F7, bibliography inference | Spaces, tabs and newlines before the bibliography argument select BibTeX and discover the same files. |
| O1/O2, repeated scans | One environment-directory check for 100 files in one directory; one dependency scan per document when planning two documents. |
| O3, snapshot wait | A file created while waiting for the lock is present in the snapshot's Git tree. |

## Independent review

A separate model reviewed the source and attempted independent overwrite,
freshness and integrity probes. It found the omitted `.lol` output and the
generated-suffix source exclusion; follow-up probes added literal output-path
sources, scripts and Makefiles. All are fixed and covered here.

The broader suite then caught a regression where a Make goal was treated as an
input. The review also caught attached Makefile options and ordinary output
arguments. Corrected input-role handling now distinguishes known executable,
interpreter-script and explicit Makefile reads from ambiguous arguments.

Final independent review found no remaining actionable findings. It ran all
25 scope tests, 13 lifecycle tests and three existing Make tests: 40 passed,
one failed in the process environment described below; none were excluded or
reported as passing. The original overwrite probes now fail before mutation
and preserve the exact source bytes.

## Limits and open items

- This execution environment exposes host process IDs in `/proc` while Python
  receives different namespace IDs. Three existing process-identity tests fail
  on unchanged 4.8.0 too: `test_a10_zombie_owner_is_not_running`,
  `test_killed_build_owner_keeps_ownership_while_its_compiler_runs`, and
  `test_process_identity_without_proc_still_detects_a_reused_pid`.
  They remain enabled. Hosted CI is the verification of these cases.
- A biber-dependent test skips because biber is absent; the unreadable-folder
  test skips as root, and real GNU Make 3.81 is unavailable. These are recorded
  skips, not passing platform claims.
- Output protection enumerates conventional outputs and known/declared inputs.
  It does not sandbox arbitrary TeX `\openout` or custom-command writes.
  Macro-built paths and ambiguous command inputs still need declarations.
- macOS, Windows, launchd and network-file-system locking were not exercised.
  The existing platform limitations and snapshot retention policy are unchanged.
- The owner's G1/G2/G3 decisions and plan steps 3.7/3.8 remain open; this repair
  does not change permission guardrails, routing policy gates or the manual.
