# Version 4.1.0 verification

This records the release that removes the generator of CI workflows (the second step of [the minimal scope](minimal-scope.md)), tested on
2026-10-13 on macOS (Darwin 25.5, Python 3.14.8, GNU Make 4.4.1 from Homebrew with `gnubin` first on `PATH`, TeX Live with latexmk 4.88 and
Biber 2.21). The hosted results of the pull request follow once it has run.

| Check | Result |
|---|---|
| `tests/test_scope_4_1_0.py` against 4.0.0 | 15 failures across its five tests (the generator, its options, the configuration, the install and the document views are all still there) |
| The same after the change | All 6 pass (a test of the upgrade was added). Four mutations (a generator function back, the `--no-ci` option back, `integrations.ci` accepted, the upgrade no longer dropping it) are each caught |
| `make -C workbench test` | 371 tests, 1 skipped (`test_a10_zombie_owner_is_not_running` needs `/proc`, which macOS lacks). 379 became 365 after removing the 14 tests of the generator, the pinned-action tests of the generator and the acceptance workflow's check, and 6 new tests make 371 |
| `make -C workbench portability` | 74 of 74, as in 4.0.0 |
| The generated-files guard | Regenerated on purpose and read: the workflow copies are gone from every fixture, the Makefile and editor copies are byte-identical, and `profile-writing-no-editor` replaces `profile-writing-no-editor-no-ci` (its Makefile is the same text). The stored build views lose their `ci` entry |
| 4.0.0 and this tree installed into identical projects, every surviving action, five argument variants, `core`, `writing` and a project without configuration | 315 invocations, 8 differences: the six `issue` report names (timestamps) and the two `status --json` configurations, which no longer show `integrations.ci` |
| A 4.0.0 `writing` project installed with its default CI and editor, upgraded by this tree | A dry run writes nothing and names two notes. The upgrade succeeds and changes the runtime files, `AGENTS.md` and `.latex-ai.json` (the `ci` setting dropped). The workflow stays byte-identical and is no longer in the manifest; the Makefile and both editor files are byte-identical; a second upgrade says "Already current" and repeats no note |
| `latex-ai-init audit` in the reference, `make latex-ai-bib-check`, `make check` | Current; both checks pass |

## Found on the way

- Removing the setting that switched PDF export (`pdf_artifact`) would have turned `make pdf-artifact` into an always-on command, which is what
  it is now; no test depended on the switch, but the tests that configured it had to lose the setting too.
- The reference's own workflow was generated by the code being removed. It is a plain file now, simpler than before: the planner-driven steps
  existed to run only what a change needed, and the repository's checks are cheap enough on a public repository to run whole.

## Not verified

- **Hosted runs of the new `latex.yml`.** It has not run on GitHub; the pull request is its first run. The ruleset requires its job, `validate`.
- **Python 3.10 to 3.13**, **GNU Make 3.81 as `make`**, **Windows.**
- **An upgrade of a 3.x project.** Only the step from 4.0.0 was tried.
