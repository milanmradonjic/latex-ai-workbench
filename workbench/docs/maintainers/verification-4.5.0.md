## Found on the way

- **Two checks that tests could not reach.** The first mutation run did not catch accepting xelatex or biber in `latex.defaults`: the document-level check refuses them anyway once the defaults are resolved into a document. The default checks stay, because a default that every document overrides is still a wrong default and is better refused where it is written; the tests now include such a default.
- **A mutation that did not mutate.** The "reads a magic comment" mutation searched the source text with its comments already stripped, so it changed nothing; it now reads the file as the old code did.
- **A fixture that was wrong, not the code.** The first version of the BibTeX detection test failed on 4.4.2 for a missing `.bib` file, not for the behaviour; the fixture gained its file.
- **Fixtures named after what is gone.** `profile-core` and the rest are renamed after what they hold, so that the word "profile" does not survive in the tests of a tool that has none.
- **Left alone:** the maintainers' README still says the managed CI workflow classifies changes for Pandoc and package tests (it went with 4.1.0); `export.format` is a required key with a single legal value (making it optional is a small follow-up); `status`, `guide` and `documents` print `pdflatex` for a document whose `build_command` runs something else; five imports that were already unused before this step (`integrations` in `schema.py`, `has_module` in `latex.py`, `PurePosixPath` in `core.py`, `VALIDATION_ACTIONS` and `atomic_write` in `runtime.py`).
- **A decision, not an omission.** `init` on a paper that needs lualatex, xelatex or biber now succeeds as pdflatex, and the first build fails with the compiler's own message. A guard that read the source for those would bring back the inference this step removes; `installing.md`, `configuration.md` and `migrating.md` say what to declare instead.

## Independent review

An agent that was given the intent of the step and the diff, not these results, reviewed it, ran the suite, `portability` and its own comparisons, and found no regression for a project that uses only what stays; every receipt 4.4.2 wrote for four projects (a BibTeX paper, a `build_command` project, two documents, a copy of the reference) was judged current by 4.5.0. What it found, and what was done:

| Finding | Disposition |
|---|---|
| `init` no longer recognises a biblatex paper with `backend=bibtex` (4.4.2 wrote `backend: bibtex` and a bibliography module) | Confirmed. Not restored: biblatex goes with biber, and the by-hand setting is one line. Stated as a loss in the release notes and in `installing.md` |
| The refusal's hint said "declare a build_command" to a document that already has one, which is exactly what 4.4.2's docs prescribed (`--engine lualatex --build-command ...`); the format hint was irrelevant; a missing format read "None is not supported"; a document's backend was named `bibliography.backend` | Confirmed by upgrading such a project. Each setting now has its own hint (for the engine: remove the setting), a missing format says so, and the label is "bibliography backend" |
| `status`, `help` and `guide` showed a refusal without its hint, and advised restoring a last good copy that is the same configuration | Confirmed. They print the hint (`edit .latex-ai.json: remove the engine setting ...`); a problem with no hint keeps the old advice; test added |
| `diff` and `runtime` stop at a refused setting, but the upgrade recipe puts the edit after them | Confirmed. A line in `upgrading.md` says to make the edit first |
| Nothing pinned "receipts byte-identical"; renaming the identity key left the suite green | Confirmed. A frozen 4.4.2 receipt must be judged current, and the identity has a literal; both caught by mutations |
| The diagnostic test compared the tuple with a copy of itself; a loop with one element | The test now reads the report's tool names; the loop is a plain assertion |
| The allowed values were written in seven places | One definition each (`ENGINES`, `BACKENDS`, `EXPORT_FORMATS` in `core.py`), used by `schema.py` and by the check in `build_identity` |
| The release notes promised a biber project "its own log reading"; `tex-notes.md` said a document may override `engine`; a test-line count was off by two; nothing said what a biber user does with a Zotero export | Corrected, corrected, recomputed, and `bibliography.md` and the skill now say: list the `.bib` under `bibliography.files`, leave `export` null |
| `export.format` is required with a single legal value; some displays print `pdflatex` for a `build_command` document | Left, listed above |

## Not verified

- **Hosted runs of this pull request**, with TeX Live 2026 in the `validate` job (the local TeX is 2023).
- **Other platforms and versions locally.** macOS, Windows, and Python 3.10 and 3.14 were not run locally; the hosted run covers all five Python versions on Linux.
- **A real build with lualatex, xelatex or biber through a `build_command`** after upgrading: the path is the one `build_command` always had, and it was not exercised here, since this install has neither engine nor biber.
- **A receipt written by 4.4.2 and read by 4.5.0**, beyond the comparison of what both write for the same project (identical).
- **An outside script that passed `--engine`, `--backend` or `--profile`**: none is known in this repository; one would now get an argparse error.
