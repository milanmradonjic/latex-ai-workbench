## Found on the way

- **Two checks that tests could not reach.** The first mutation run did not catch accepting xelatex or biber in `latex.defaults`: the document-level check refuses them anyway once the defaults are resolved into a document. The default checks stay, because a default that every document overrides is still a wrong default and is better refused where it is written; the tests now include such a default.
- **A mutation that did not mutate.** The "reads a magic comment" mutation searched the source text with its comments already stripped, so it changed nothing; it now reads the file as the old code did.
- **A fixture that was wrong, not the code.** The first version of the BibTeX detection test failed on 4.4.2 for a missing `.bib` file, not for the behaviour; the fixture gained its file.
- **Fixtures named after what is gone.** `profile-core` and the rest are renamed after what they hold, so that the word "profile" does not survive in the tests of a tool that has none.
- **Left alone:** the maintainers' README still says the managed CI workflow classifies changes for Pandoc and package tests (it went with 4.1.0); `status` shows a configuration problem without the hint that the other commands print; five imports that were already unused before this step (`integrations` in `schema.py`, `has_module` in `latex.py`, `PurePosixPath` in `core.py`, `VALIDATION_ACTIONS` and `atomic_write` in `runtime.py`).
- **A decision, not an omission.** `init` on a paper that needs lualatex, xelatex or biber now succeeds as pdflatex, and the first build fails with the compiler's own message. A guard that read the source for those would bring back the inference this step removes; `installing.md`, `configuration.md` and `migrating.md` say what to declare instead.

## Not verified

- **Hosted runs of this pull request**, with TeX Live 2026 in the `validate` job (the local TeX is 2023).
- **Other platforms and versions locally.** macOS, Windows, and Python 3.10 and 3.14 were not run locally; the hosted run covers all five Python versions on Linux.
- **A real build with lualatex, xelatex or biber through a `build_command`** after upgrading: the path is the one `build_command` always had, and it was not exercised here, since this install has neither engine nor biber.
- **A receipt written by 4.4.2 and read by 4.5.0**, beyond the comparison of what both write for the same project (identical).
- **An outside script that passed `--engine`, `--backend` or `--profile`**: none is known in this repository; one would now get an argparse error.
